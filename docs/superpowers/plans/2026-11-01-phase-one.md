# Phase 1 implementation plan

**Goal:** Deliver the command-line backup and restore milestone in `possible-workflow.md`.

**Architecture:** Retain .NET 10, the reusable core library, CLI and xUnit projects. Use file-level incremental storage: each immutable manifest describes a complete directory tree and references files in the snapshot that actually copied them. Full mode copies every file. SHA-256 determines content changes, independent of timestamps. Stage snapshots under `.pending-*`; rename into place only after verifying copies. Keep previous snapshots indefinitely.

**Constraints:** Do not commit `.gitignore`, `possible-workflow.md`, `README.md`, or the pre-existing deletion of `scaffold.ps1`. Use subject-only conventional commit messages. Build in the current checkout to preserve the supplied local workflow and ignore settings. No later-phase scheduling, desktop UI, retention, exclusions or selective restore.

## Review focus

- Every snapshot is independently restorable after source changes/deletions; referenced earlier snapshot files remain present.
- A failed/cancelled backup cannot be mistaken for a complete one; abrupt process termination leaves only recoverable staging.
- Paths from configuration and manifests cannot recurse into storage, traverse out of roots or follow filesystem links.
- Restoring corrupt content fails visibly and cannot overwrite existing user files.
- Multi-source aliases stay unambiguous, and empty directories and zero-byte/binary files survive restoration.
